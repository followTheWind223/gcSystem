# 游戏区服管理与结算

已实现，契约 2.2.0，数据库迁移 V006。后台入口：商城管理 → 游戏区服（`/gameshop/game-servers`），分类列表也可点“管理区服”。区服属于单个游戏，名称、排序、启用状态和备注由管理员维护；所属游戏创建后不可更换。

## 数据与后台操作

新增 `mall_game_server`，13 字段明细见[字段字典](../database/字段字典.md#mall_game_server-游戏区服)，实际 SQL 为 [V006](../../system/sql/migrations/V006__game_servers.sql)。同游戏内未删除名称唯一（含停用记录），删除为软删除；重新创建同名区服会获得新的 ID。默认迁移仅为已有游戏建立一区、二区、三区，不将其视为真实游戏官方区服；管理员可直接修改为实际名称。新建游戏需要手动添加区服。

| 方法与资源 | 权限 | 成功 HTTP | 用途 |
| --- | --- | --- | --- |
| GET /mall/game-servers | mall:server:list | 200 | 按 categoryId、keyword（最长80）、status 分页，pageSize 最大50 |
| GET /mall/game-servers/{serverId} | mall:server:query | 200 | 读取编辑前当前版本 |
| POST /mall/game-servers | mall:server:add | 201 | 新建，Location 指向新资源 |
| PUT /mall/game-servers/{serverId} | mall:server:edit | 200 | 完整替换，携带 version；启停也使用此接口 |
| DELETE /mall/game-servers/{serverId} | mall:server:remove | 200 | 幂等软删除 |

POST/PUT 的 categoryId、name、sort、status、remark 键均必有（remark 可为null）；PUT 还必有 version。

后台选择游戏另需 `mall:category:list`，菜单迁移不自动授权普通角色。请求与每一种错误的完整 JSON 见[管理端逐接口说明](./管理端接口详细说明.md#adminListGameServers-后台查询游戏区服)，字段级类型以 [OpenAPI](./openapi.yaml) 为准。

## 创建订单

新客户端使用 `deliveryInfo.serverIds`，每个必需游戏恰好一个正整数 ID 字符串（最长19位、数组1–50项、不重复）。禁止传错游戏、漏选、多选同游戏；同时传非空 serverName 与 serverIds 返回400。游戏账号、角色仍按报价 deliveryFields 要求填写，备注选填。

```json
{
  "requestKey": "3153d0a1-22df-4480-a34d-0c86d95d045b",
  "quoteToken": "mock-quote-token-0001",
  "deliveryInfo": {
    "gameAccount": "demo_game_account",
    "serverIds": [
      "1"
    ],
    "roleName": "星海旅人"
  },
  "remark": "请按角色名核对后交付。"
}
```

HTTP201（首次创建）/200（相同请求幂等重放），外壳 code 均为200。订单 deliveryInfo 返回服务端规范化的名称及快照：

```json
{
  "deliveryInfo": {
    "gameAccount": "demo_game_account",
    "serverName": "一区",
    "roleName": "星海旅人",
    "servers": [
      {
        "serverId": "1",
        "categoryId": "101",
        "categoryName": "星海远征",
        "serverName": "一区"
      }
    ]
  }
}
```

跨游戏时 `servers` 每个游戏一项，`serverName` 为最长100字符的兼容摘要，完整展示应读 servers。单游戏 serverName 直接为区服名称。旧历史订单响应 servers=[]，仍可展示其原有 serverName；不得通过当前区服配置反向改写历史交付信息。

参数缺失、重复、跨错游戏、同游戏多选返回 HTTP400 / MALL_VALIDATION_FAILED。所选区服在报价后被停用/删除或不存在，返回 HTTP409：

```json
{
  "code": 409,
  "msg": "所选游戏区服已停用或不存在，请重新选择。",
  "errorCode": "MALL_SERVER_UNAVAILABLE",
  "data": null
}
```

客户端应重新获取报价并重新选择；整单失败不扣库存、不生成订单。后台修改旧版本返回409 / MALL_VERSION_CONFLICT，同游戏重名返回409 / MALL_DUPLICATE_VALUE。所需资源不存在返回404 / MALL_RESOURCE_NOT_FOUND；未登录401，缺少后台权限403。

## 事务和兼容

创建订单和管理区服均先锁游戏，再锁区服。订单在同一事务校验当前启用状态、所属游戏及选择完整性，再保存快照和扣库存；停用与下单并发时按锁串行化。已生成的待支付订单继续按原快照支付/取消，不受后来配置变化影响。

旧客户端的 deliveryInfo.serverName 暂时保留，但必须匹配每个必需游戏中当前启用的真实名称；禁止自由文本。旧请求摘要保持原三字段形式；幂等重放先查已有订单，因此配置删除或报价过期后仍返回原订单。新客户端应采用 serverIds。

应用库已备份并迁移V006，9个默认区服；迁移重复执行不恢复人工删除/停用的区服，也不覆盖原有业务记录。新环境按 V001–V006 顺序执行；如需 D001 隔离演示，请先导入D001再执行V006，或手动给演示游戏添加区服。
